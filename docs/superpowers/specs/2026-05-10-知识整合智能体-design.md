# 学科知识整合智能体 — 系统设计规格

## 一、项目概述

为「第一届AI全栈黑客松」开发的Web应用。帮助教师将7本医学教材整合压缩到原始体量30%的精华版本，构建交互式知识图谱，提供RAG精准问答和多轮对话能力。

**比赛时长**：5小时

## 二、核心需求

### 必须实现（P0）
1. 多格式教材加载与解析（PDF/MD/TXT）
2. 单本教材知识图谱构建与可视化
3. 知识图谱交互（点击、缩放、拖拽、搜索）
4. 跨教材知识图谱整合（语义对齐+去重，压缩到30%）
5. RAG精准问答（带来源引用）
6. Agent架构设计文档
7. 多轮对话修改整合方案
8. Web交互界面（SPA单页）
9. 整合报告输出
10. 开发文档

### 加分项（P1/P2）
- 多视图图谱、混合检索+Rerank、Docker部署、自建RAG Benchmark
- P2技术报告（3000-8000字，需实验数据）

## 三、技术选型

| 层级 | 选择 | 理由 |
|------|------|------|
| 后端框架 | Python FastAPI | 异步支持好、生态丰富、赛题推荐 |
| 前端框架 | Vue 3 + Vite | 响应式数据绑定、SFC组件化、HMR热更新 |
| LLM | DeepSeek API | 便宜、中文强、适合大量调用 |
| Embedding | BGE-small-zh | 中文优化、本地免费运行 |
| 向量库 | FAISS | 轻量、零部署、Python原生 |
| 图谱可视化 | ECharts | 中文文档好、力导向图内置 |
| Agent架构 | 单Agent Pipeline | 5小时可控、调试方便 |
| 文件解析 | PyMuPDF (PDF) + native (MD/TXT) | 成熟稳定 |
| 模型运行 | sentence-transformers 本地 | 省钱、离线可用 |

## 四、页面布局

三栏布局（1920×1080），从左到右：

### 左侧面板（280px）— 教材管理区
- 拖拽/点击上传区域（PDF/MD/TXT）
- 教材文件列表（文件名、格式、大小、解析状态）
- 教材来源颜色标识

### 中间区域（弹性）— 知识图谱可视化
- 力导向图主视图（ECharts）
- 顶部工具栏：节点/关系统计、搜索框、视图切换
- 图例：教材颜色映射 + 关系线型说明
- 节点：圆形，颜色=教材来源，大小=跨教材频次
- 关系线：4种线型（实线=依赖、虚线=并列、箭头=包含、空心=应用）
- 交互：滚轮缩放、拖拽画布、拖拽节点、点击弹出详情面板
- 详情面板：知识点名称、定义、教材来源、频次、关联关系

### 右侧面板（360px）— 功能面板（4个Tab）

**Tab 1 — 整合操作**
- 压缩比统计卡（原始字数 → 整合后字数 → 压缩比%）
- 整合决策列表（合并/保留/删除，带置信度和理由）
- 每条决策显示受影响的教材来源
- 「执行整合」按钮

**Tab 2 — RAG问答**
- 索引状态（已索引X本，共X个知识块）
- 问题输入框 + 提问按钮
- 回答区域：正文 + 来源引用列表
- 每条引用：教材名、章节、页码、相关度分数
- 点击引用可展开查看原文chunk

**Tab 3 — 多轮对话**
- 对话气泡（教师↔系统）
- 教师可要求修改整合决策
- 系统反馈调整结果
- 对话历史在当前会话内持久化

**Tab 4 — 整合报告**
- 统计表格（原始教材数、字数、压缩比、节点/关系变化）
- 决策分类统计（合并X/保留X/删除X）
- 导出Markdown按钮

### 数据流（完整链路）

```
上传教材 → 解析章节结构 → 逐章调用LLM提取知识点(JSON)
  → 构建知识点节点+关系边 → 每本教材独立存储
  → Embedding计算语义相似度 → 跨教材去重对齐
  → 整合决策(merge/keep/remove) → 压缩到30%
  → 分块+向量索引 → RAG问答就绪
  → 对话反馈 → 更新整合决策 → 图谱实时更新
```

## 七、关键设计决策

### 为什么单Agent Pipeline？
- 5小时时限，多Agent需要额外的通信协议、状态同步和错误隔离代码
- 赛题评分看设计论证深度而非Agent数量
- Pipeline各模块有明确的输入/输出接口，职责清晰
- 后续可以自然演进为多Agent架构（模块间已有边界）

### 为什么BGE-small-zh？
- 专为中文语义检索优化，比多语言模型效果好
- sentence-transformers本地运行，无需API调用
- 模型小（~100MB），加载快，对7本教材的处理在可接受范围内

### RAG分块策略
- 每chunk 500-800字，相邻重叠100字（sliding window）
- 理由：医学概念通常在一段内完整表达，500-800字能覆盖完整概念描述+上下文
- 重叠防止知识点在chunk边界被截断

### 整合对齐策略
- 双重对齐：先BGE Embedding计算余弦相似度（快速筛选），相似度>0.8的候选对再送LLM判断（精准）
- 阈值0.8：较低的阈值减少漏报，LLM二次判断过滤误报
- 这样在成本和准确性间取得平衡

- [ ] README能让别人部署运行
- [ ] 整合报告包含5项必需内容
