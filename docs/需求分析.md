# 需求分析

## 问题背景

在当前高校教学体系中，同一学科领域往往存在多本教材并行使用的现象。这些教材由不同出版社出版、不同作者编写，虽然各有侧重，但彼此之间存在大量的内容重复。以医学教学为例，7本核心教材（局部解剖学、组织学与胚胎学、生理学、医学微生物学、病理学、传染病学、病理生理学）之间存在大量知识重叠，学生浪费大量时间在重复阅读上，教师难以系统评估教材间的交叉与缺失。

## 子问题分解

### 1. 知识点粒度定义

**问题**：知识点应该多细？一个概念是一个知识点，还是一个概念的不同方面分别算多个知识点？

**决策**：以"可独立教学的最小单元"为粒度。例如「炎症」是一个知识点（包含定义、机制、表现），而「炎症的血管反应」属于「炎症」的子概念，归为包含关系。每个知识点由 LLM 从章节内容中提取，包含名称、一句话定义和类别标签。

### 2. 重复判定标准

**问题**：如何判定两本教材中的知识点是"同一个"？

**决策**：双重对齐策略——
1. **粗筛**：BGE Embedding 计算语义相似度，余弦相似度 > 0.8 视为候选重复对
2. **精判**：高相似候选对送 LLM 判断是否等价，并选择描述最完整、最系统的版本作为合并目标

### 3. 教学连贯性保障

**问题**：压缩删除后如何保证知识体系不断裂？

**决策**：
- 保留知识点之间的依赖关系图谱（prerequisite/parallel/contains/applies_to）
- 删除节点前检查是否存在依赖链——如果被删节点是其他保留节点的前置依赖，系统标记警告
- 整合报告中包含「教学完整性说明」章节

### 4. 压缩比计算方式

**问题**：压缩比按什么维度计算？

**决策**：按字数计算。
- 原始总字数 = 所有已加载教材的字数之和
- 整合后字数 = 去重合并后保留内容的字数（通过节点数比例映射）
- 压缩比 = 整合后字数 / 原始总字数，目标 ≤ 30%

### 5. RAG分块策略选择依据

**问题**：chunk 应该多大？是否需要重叠？

**决策**：600字/chunk，100字重叠（sliding window）。

**依据**：
- 医学概念通常在一段内完整表达，500-800字能覆盖完整概念描述加上下文
- 100字重叠防止知识点在 chunk 边界被截断
- 过小（<300字）会丢失上下文，过大（>1000字）会稀释检索精度
